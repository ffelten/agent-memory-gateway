# Agent Memory Gateway Implementation Plan

> **For agentic workers:** Execute independent storage/deployment and telemetry tasks in parallel with gateway policy work; review their boundaries before integration. Track checks below.

**Goal:** Implement Ash's protected gateway against Florian's existing client, with testable authorization and deployable AWS configuration.

**Architecture:** A Python Lambda HTTP adapter calls a policy service backed by authoritative DynamoDB records. Provider operations use Florian's Senso adapter; a test-only provider exercises local security behavior. A metadata-only outbox feeds ClickHouse independently of authorization.

**Tech Stack:** Python 3.12, boto3, AWS SAM, DynamoDB, Secrets Manager, pytest.

## Global constraints

- Agents hold only run-scoped gateway credentials. Authentication precedes body processing.
- 32 KiB JSON body limit; unknown fields rejected. Direct unauthorized memory IDs return 404.
- PENDING/QUARANTINED/INGESTING/REVOKED are unreadable. APPROVED requires current authorization.
- Explicit denial wins. Empty scope never calls provider search. Revocation commits locally first.
- No production fallback to mock provider. No raw payloads in logs, errors, or analytics.
- Florian owns real Senso, agents, and demo; do not modify those lanes.
