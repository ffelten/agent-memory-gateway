### 1. Document not searchable after upload  
**Possible reasons**  
- Ingestion/compilation is still in progress.  
- The node was moved to a folder the API key cannot see.  

**What to do**  
1. **Poll the compile status** – call `GET /org/kb/nodes/{id}` and check `content.processing_status`.  
   - Keep polling every ~15 seconds until the status reads **complete**.  
2. If the node was moved, verify the key’s folder permissions (see *Permissions*).  
   - Use `GET /org/api-keys/{key_id}/kb-permissions` to confirm the key can see the target folder.  

---

### 2. “404 – node missing, or no permission for it” error  
**Why it happens**  
- The requested node does not exist **or** the API key lacks access to that folder.  
- Senso deliberately returns the same message for both cases to prevent probing.  

**Remedy**  
- Confirm the node ID is correct (node IDs identify positions in the tree).  
- Check the key’s KB scope on the **API Keys** page under *KB Access*.  

---

### 3. Duplicate‑document error (409)  
**Cause**  
- Uploading text that is identical to an existing document.  

**Fix**  
- Do not re‑upload the same markdown/plain‑text.  
- If an update is required, fetch the current version (`GET /org/kb/nodes/{id}/content`), modify the content, and POST the **full new version** (updates replace the body, they don’t append).  

---

### 4. Move or delete appears not to take effect immediately  
**Explanation**  
- Moves and deletes are queued, not instantaneous.  
- Answers may still reference the document until the queue settles.  

**Steps to verify**  
1. Call `GET /org/kb/sync-status` and wait until `syncing` is **false** (org‑wide structural changes).  
2. For a single document, keep polling `GET /org/kb/nodes/{id}` and read `content.processing_status`.  

---

### 5. Permission‑related “403 – the key has no grant covering that node”  
**Root cause**  
- The API key is scoped to a folder that does not include the target node.  

**Resolution**  
- Scope the key to the appropriate folder on the **API Keys** page (requires a signed‑in session).  
- Re‑query the key’s permissions to ensure the folder is included.  

---

### 6. Version‑related confusion (node id vs. content id)  
**Issue**  
- Supplying a content ID where a node ID is expected (or vice‑versa) – the most common integration mistake.  

**Check**  
- Node IDs refer to tree positions (documents or folders).  
- Content IDs appear in search results and identify compiled content for citation.  

**Fix**  
- Verify you are using the correct identifier for each endpoint.  

---

### Quick CLI checks  

| Task | CLI command |
|------|-------------|
| List top‑level files | `senso kb my-files --output json` |
| Create a folder | `senso kb create-folder --name &quot;Policies&quot;` |
| Find a document | `senso kb find --query &quot;refund&quot;` |
| Upload a file | `senso kb upload handbook.pdf --folder-id &lt;id&gt;` |
| Re‑process after move/delete | `senso ingest reprocess &lt;node-id&gt;` |

---  

**When all above steps fail:** capture the exact request/response, double‑check API key scope, and raise a ticket with the Senso support portal, attaching the node ID, content ID (if applicable), and any error codes returned.
