# Gateway audit telemetry

The gateway calls `analytics.events.record_event(store, **fields)` after its
decision and before returning a successful response. The function persists one
record under kind `event`, generates `event_id`, UTC `timestamp`, and
`policy_version`, and returns the saved record with `_rev`. Its only accepted
caller fields are:

`trace_id`, `tenant_id`, `principal_id`, `run_id`, `memory_id`,
`application_version`, `operation`, `transport`, `decision`, `reason_code`,
`gate_ms`, `senso_ms`, and `total_ms`.

IDs must be canonical UUIDs (hex or hyphenated) except the registered demo IDs
`tenant-demo`, `eng-alpha`, and `eng-beta` in their appropriate fields. Absent
identity/version values are null; `trace_id` is required. Operation, transport,
decision, and reason are closed enums. Application versions are positive
integers, and timings are finite nonnegative numbers. Unknown fields and invalid
values fail with a bounded error containing none of the rejected content.
Timings are measured by the gateway, not generated by the exporter. Do not pass
request text, queries, credentials, addresses, URLs, prompts, or provider errors.

`analytics.worker.flush_pending(store, sink, limit=100)` revalidates a batch,
calls `sink.insert(rows)`, then conditionally marks each record delivered using
its original revision. Delivery failures, malformed records, and acknowledgement
conflicts remain pending. A crash or acknowledgement conflict can insert the
same `event_id` again: this is **at-least-once delivery**, not exactly once.
Delivered events are retained in the outbox. This demo worker lists the event
partition each invocation; its full scan of that partition is not a claim of
production-scale queue throughput.

Apply `schema.sql` in the configured ClickHouse database using trusted operator
credentials. The worker does not create databases or tables. Its ClickHouse
identity needs INSERT on `gateway_events`; the display identity can have SELECT.
`ReplacingMergeTree` removes duplicate sorting keys during background merges.
Use `FROM gateway_events FINAL` for accurate counts before merges finish, or
deduplicate by `event_id`. The event timestamp stays identical on retries.

The canonical time column is `timestamp`; Florian's display can select
`timestamp AS ts`. For example:

```sql
SELECT timestamp AS ts, trace_id, operation, decision, reason_code,
       gate_ms, senso_ms, total_ms
FROM gateway_events FINAL
ORDER BY timestamp DESC
LIMIT 100;
```

The scheduled Lambda entrypoint is `analytics.worker.lambda_handler`. It reads
`GATEWAY_TABLE` and `CLICKHOUSE_SECRET_ARN` from its environment. The secret must
be a JSON object with exactly `url`, `username`, `password`, and `database`.
`url` must be an HTTPS root URL with no credentials, query, fragment, or custom
path. `database` must match `[A-Za-z_][A-Za-z0-9_]{0,63}`. Credentials travel only
in the HTTPS Authorization header. No HTTP fallback is available.

The sink uses an explicit column list with `FORMAT JSONEachRow`, synchronous
inserts, `wait_end_of_query=1`, and best-effort ISO timestamp parsing. It rejects
redirects, limits the request to 1 MiB, reads at most 4097 response bytes, and
uses a 5-second socket timeout. Only HTTP 200 with an empty response and no
ClickHouse exception header counts as success. Error bodies are neither logged
nor returned. AWS SDK calls also use bounded connection/read timeouts. The Lambda
timeout bounds the overall scheduled invocation; socket timeouts alone are not
a total elapsed-time limit.

Protocol references: [ClickHouse HTTP interface](https://clickhouse.com/docs/interfaces/http)
and [ReplacingMergeTree](https://clickhouse.com/docs/engines/table-engines/mergetree-family/replacingmergetree).

Local verification: `.venv/bin/python -m pytest tests/analytics -q`. Tests use an
injected HTTPS transport and local AWS emulation. They do not establish a live
ClickHouse insert/query round trip or a deployed AWS worker.
